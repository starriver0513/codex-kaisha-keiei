SECTION 01

テクニック1：会社経営フォルダの構築

まずCodexが作業するフォルダを作る

Codexはローカルフォルダで作業します。ローカルフォルダとは、MacでいうFinder、Windowsでいうエクスプローラーで見ているファイルやフォルダのことです。

最初はCodexのデスクトップアプリだけでOKです。ターミナルというエンジニア向けの使い方もありますが、会社経営やマーケティングで使う分には、見慣れたチャット画面でフォルダを選んで指示できるデスクトップアプリから始めるのが分かりやすいです。

この情報がない状態でCodexに仕事を頼むと、どうしても一般論になりやすいです。会社情報、商品情報、過去の発信が入ると、自分の事業に合わせて判断しやすくなります。

最初に入れる情報

会社・事業情報

事業概要、商品、価格、ターゲット、提供価値、よくある質問。

発信・制作物

過去のYouTube台本、X投稿、LINE配信、セミナー資料、LP。

業務情報

業務手順、担当者、使用ツール、確認ルール、お客様対応の基準。

一撃構築プロンプト

フォルダは、ただ情報を入れるだけではなく、AIにとって読み取りやすく整理して入れる必要があります。以下のプロンプトを使うと、会社経営用の初期フォルダをまとめて作れます。

会社経営フォルダ 一撃構築プロンプト 
このフォルダを、Codexで会社経営・SNS運用・講座運営・商品設計を進めるための作業フォルダとして整理してください。

目的は、AIが会社情報・商品情報・過去の制作物・業務ルールを読み取り、実務に使える出力を作れる状態にすることです。

以下の方針でフォルダ構造を作成してください。

1. 会社全体の情報
- 会社概要
- 事業概要
- 商品・サービス情報
- ターゲット・顧客情報
- よくある質問

2. 事業部ごとの情報
- SNS運用
- 講座運営
- 商品設計
- セールス
- 顧客対応
- 経理・管理

3. 制作物
- YouTube台本
- X投稿
- LINE配信
- セミナー資料
- LP・販売ページ
- お客様の声・実績

4. AIに守らせるルール
- 言葉遣い
- 出力先
- 確認が必要な操作
- 扱ってはいけない情報
- APIキーや顧客情報の管理ルール

5. 今後スキル化したい業務
- 業務名
- 目的
- 手順
- 使う情報
- 出力形式
- 人間確認が必要な部分

作成後に、
「どのフォルダに何を入れればいいか」
「最初に入れるべきファイル」
「不足している情報」
を初心者にも分かる言葉で説明してください。
  • フォルダ名は、あとから見ても意味が分かる名前にする。
  • 会社情報と制作物を混ぜず、事業部や業務領域ごとに分ける。
  • 顧客情報やAPIキーを入れる場所は、最初から扱いを分ける。
  • 作っただけで満足せず、実際の資料や過去制作物を入れる。

テクニック2：ルールファイルの作成

Codexに毎回守らせるルールを作る

会社経営フォルダを作ったら、次にやるのがルールファイルの作成です。CodexではAGENTS.mdというファイルを使います。これは、Codexに毎回守らせるルールを書くファイルです。

OpenAIのドキュメントでも、Codexは作業前にAGENTS.mdを読み、プロジェクトごとの指示として扱うと説明されています。つまりAGENTS.mdは、AIに「この会社ではこう動いてください」と伝えるための基本ルールです。

公式情報: Custom instructions with AGENTS.md

AGENTS.mdに入れる内容

仕事の前提

このフォルダの目的、扱う事業、見るべき資料、出力先。

禁止事項

勝手な削除、上書き、外部送信、APIキー表示、架空数字の生成。

文章ルール

専門用語は簡単に説明する、事実と推測を分ける、一次情報を優先する。

確認ルール

送信、投稿、決済、削除、権限変更は人間確認を挟む。

AGENTS.md作成プロンプト 
このフォルダを会社経営用のCodex作業フォルダとして使いたいです。

まず、Codexが毎回守るべきルールをまとめた AGENTS.md を作成してください。

入れてほしい内容は以下です。

1. このフォルダの目的
- 会社経営、SNS運用、講座運営、商品設計などの業務をCodexで進めるための作業フォルダであること

2. Codexの基本ルール
- 不明点がある場合は勝手に決めずに確認する
- 既存ファイルを削除・上書きする前に必ず確認する
- 会社情報、顧客情報、APIキーなどの機密情報を外部に出さない
- 出力は初心者にも分かる言葉で説明する

3. ファイル管理ルール
- 新しく作るファイルの保存先を明記する
- 既存のフォルダ構造を勝手に大きく変えない
- 作業後に変更したファイルを簡単に報告する

4. 文章作成ルール
- 専門用語は簡単な言葉で説明する
- 事実と推測を分ける
- 一次情報がない実績や数字を作らない

上記を整理して、初心者にも分かりやすい AGENTS.md を作成してください。

テクニック3：SaaSの棚卸し

普段使っているWebサービスを洗い出す

SaaSとは、Gmail、Chatwork、Googleカレンダーのように、普段の仕事で使っているWebサービスのことです。外部ツールをCodexに操作させる前に、自分がどのツールで何をしているのかを洗い出します。

一つ一つ自分で洗い出すのが面倒な場合は、Codexとの過去の会話や、チームメンバーとのLINE、Chatwork、メールなどを渡して分析してもらいます。

SaaS棚卸しプロンプト 
これまでの私との会話ラリーを参照して、
私が普段の仕事で使っていそうなSaaSツールを洗い出してください。

もし追加でチームメンバーとのLINE、Chatwork、Slack、メールなどのやり取りを渡した場合は、
その内容も分析対象にしてください。

出力形式は以下にしてください。

- SaaSツール名
- 何の業務で使っていそうか
- そのツールに入っていそうな情報
- Codexに任せられそうな作業
- 追加で確認したい質問

推測で断定せず、
確信がないものは「可能性あり」として分けてください。

出力された一覧で見るポイント

  • そのツールに会社情報、顧客情報、予定、売上情報のどれが入っているか。
  • 読むだけでよいのか、書き込みや送信まで必要なのか。
  • Codexに任せたい作業が、確認、整理、下書き、投稿、予約のどれなのか。
  • 最初に試すなら、リスクが低い読み取り作業から始められるか。

テクニック4：API・MCP連携

SaaSを洗い出したら、連携方法を調べる

APIやMCPは、Codexから外部ツールを扱えるようにする仕組みです。SaaSの棚卸しができたら、次はCodexに公式ドキュメントベースで連携方法を調べてもらいます。

ここで特に見てほしいのが料金体系です。APIは無料で使えるものもありますが、使った分だけお金がかかる従量課金のものもあります。連携方法だけではなく、料金が発生する条件までセットで確認してください。

API・MCP連携リサーチ指示 
先ほど洗い出したSaaSツールについて、
APIまたはMCP連携ができるかをWebリサーチしてください。

必ず公式ドキュメントを優先して確認してください。

それぞれについて以下をまとめてください。

- APIまたはMCP連携ができるか
- その連携で実現できること
- 連携できないこと
- 連携するために必要なもの
- APIキーの取得方法
- Codexで接続するまでの手順
- AIに触らせてよい範囲
- 料金体系
- 従量課金の場合、何をすると料金が発生するか
- 初心者が最初に試すならどの操作から始めるべきか

公式ドキュメントで確認できた内容と
推測を分けて出してください。

テクニック5：APIキー管理

APIキーは外部ツールを操作するための鍵

APIとMCPの繋ぎ方を調べると、必ずAPIキーが出てきます。APIキーは、AIが外部ツールを操作するための鍵のようなものです。

APIキーの中には従量課金制のものがあります。インターネット上に公開してしまうと、第三者に勝手に使われて、身に覚えのない請求が届く可能性があります。APIキーは、チャットに貼りっぱなしにしない、公開ドキュメントに書かない、SNSに載せない、公開フォルダに入れない。この4つを徹底してください。

.envで管理する

.envは、APIキーなどの重要な情報を外に出さないために管理するファイルです。まずはCodexに、.env、.env.example、.gitignoreを作ってもらいます。

APIキー安全管理プロンプト 
このフォルダで外部サービスのAPIキーを扱います。
APIキーが外部に流出しないように、安全な管理環境を作ってください。

以下を実行してください。

1. .env ファイルを作成する
- 本物のAPIキーを入れる場所として使う
- まだ実際のキーは入れず、仮の値だけ入れる

2. .env.example を作成する
- 他の人に共有しても問題ないように、キー名だけを書く
- 本物のAPIキーは絶対に入れない

3. .gitignore を確認する
- .env が外部に公開されないように除外設定を入れる

4. ルールファイルにセキュリティルールを追記する
- Codexで使う場合は AGENTS.md に追記する
- Claude Codeも使う場合は CLAUDE.md にも同じルールを追記する
- APIキーをチャットに出力しない
- APIキーをログに表示しない
- APIキーを外部URLへ送信しない
- 公開前に機密情報が含まれていないか確認する
- 従量課金APIは料金体系を確認してから使う
- 顧客に届く操作、お金が動く操作、外部に公開される操作は人間確認を挟む
- 送信、投稿、決済、削除、権限変更は勝手に実行しない
- 最初は読み取りや下書き作成など、小さい操作からテストする

5. 最初の疎通確認として、安全なテスト手順を提案する

6. 変更内容を初心者にも分かる言葉で説明する

.envに入れる例

.env サンプル 
CHATWORK_API_TOKEN=ここにChatworkのAPIキーを入れる
X_BEARER_TOKEN=ここにXのAPIキーを入れる
UTAGE_API_KEY=ここにUtageのAPIキーを入れる
GOOGLE_CLIENT_ID=ここにGoogleのクライアントIDを入れる
GOOGLE_CLIENT_SECRET=ここにGoogleのクライアントシークレットを入れる
  • まずはChatworkの自分のルームを1件読むなど、小さい確認から始める。
  • X投稿やメール送信など、外に出る操作は人間確認を挟む。
  • 削除、決済、権限変更はCodex単独で実行させない。
  • API料金、権限、出力内容を確認してから任せる範囲を広げる。

テクニック7：スキル作成

良い業務フローを、毎回再現できるようにする

スキルとは、簡単に言うとAIに仕事の手順を覚えさせるものです。毎回どの情報を見るのか、どういう順番で進めるのか、どんな形で出力するのか、どこをチェックするのかをまとめます。

ただし、いきなりスキルを作ろうとしないでください。先にその業務を1回、Codexで手動実行します。スキル化は、良い流れを固定するためにやるものです。

公式情報: Codex Skills
1

1回手動で通す

企画、資料、コメント、構成、出力、FB反映まで一度やります。

2

足りない情報を見つける

曖昧だった指示、毎回見る資料、品質チェック基準を洗い出します。

3

スキルクリエイターで固定する

デスクトップアプリで「スキルクリエイターを使って」と指示すればOKです。

スキル作成プロンプト 
これまでのやり取りをもとにスキルクリエイターを使って、この業務を毎回同じ品質で実行できるスキルにしてください。

スキルには以下を含めてください。

- このスキルの目的
- 入力として必要な情報
- 参照するフォルダやファイル
- 実行する手順
- 出力形式
- 品質チェック項目
- やってはいけないこと
- 人間確認が必要な作業

YouTube台本作成スキルの実演イメージ

星川の場合は、YouTube台本作成スキルを使い、企画、競合台本、コメント欄、フォルダ内の情報、FBを読み込んで台本を作る流れをスキル化しています。

台本作成スキル 実演用プロンプト

というテーマで台本を作ってください。

SECTION 08

テクニック8：Computer Use

APIで届かない画面操作を任せる

Computer Useは、AIがブラウザやアプリの画面を見ながら操作してくれる機能です。APIやMCPは外部ツールとCodexをつなぐ方法、Computer Useは人間が画面上でやっている操作をAIに手伝わせる方法です。

方法 向いている作業 注意点
API・MCP 安定して繰り返す読み取り、作成、更新、投稿 従量課金や権限設定を確認する
Computer Use 管理画面の確認、ボタン操作、APIがないツールの操作 APIより作業時間が長くなりやすい

APIにいきなりお金がかかるのが怖い場合は、まずComputer Useで代替するのもありです。ただし、スピードや安定性を重視するならAPI、まずお金をかけずに試したいならComputer Use、という考え方が分かりやすいです。

  • 最初は画面を開く、内容を確認する、下書きを作るところまでにする。
  • クリック前、送信前、公開前は止まるように指示する。
  • 削除、決済、権限変更は必ず人間が確認する。
  • Utage管理画面、会員ページ確認、フォーム入力、スプレッドシート確認などから試す。

テクニック10：おはようスキル

朝イチに会社の状況を整理する

おはようスキルは、朝イチに動かすスキルです。Chatwork、Gmail、Googleカレンダーを読み取り、今日やるべきことを優先順位つきで整理します。

最初は手動でOKです。慣れてきたら、毎朝決まった時間に動くオートメーションと組み合わせます。すると朝イチから、仕事の全体像が見えた状態で動き出せます。

Chatwork

自分宛ての連絡、未対応タスク、確認が必要な連絡を拾う。

Gmail

返信が必要そうなメール、期限が近い連絡、重要な案内を拾う。

Googleカレンダー

今日の予定、準備が必要な会議、空き時間を確認する。

おはようスキル 初期プロンプト 
おはようスキルとして、今日の仕事を整理してください。

確認する対象は以下です。

- Chatworkの自分宛て連絡、未対応タスク、確認が必要な連絡
- Gmailの返信が必要そうなメール、期限が近い連絡、重要な案内
- Googleカレンダーの今日の予定、準備が必要な会議、空き時間
- フォルダ内のタスクメモ、進行中プロジェクト、締切

出力形式は以下にしてください。

1. 今日の最重要タスク
2. 午前中にやること
3. 午後にやること
4. 返信が必要な連絡
5. 今日の予定
6. 先に確認した方がいいリスク
7. AIに任せられる下準備

推測で断定せず、
分からないものは「要確認」としてください。
送信、投稿、削除、権限変更は勝手に実行しないでください。
おはようスキルがあると、Codexが単発で仕事をするだけではなく、毎日会社の状況を確認して、今日の動き方を整理してくれる状態になります。
